Per-point causal deskew vs single-pose batch transform: within-frame distortion

If near-field points were transformed to world frame with one pose per frame (10 Hz, the platform's own /aft_mapped_to_init) instead of this fork's actual per-point causal deskew, how much positional error would that introduce within a single ~50 ms frame? Measured (not simulated) on a real aggressive-motion segment of swarm1's flight (~1.5 m/s translational, restarted from a calm IMU-init point ~6s before the fast segment). X-axis is each point's own offset from the frame's reference-pose time; Y-axis is the 3D distance between that point's naive single-pose position and its true per-point causally-deskewed position.
